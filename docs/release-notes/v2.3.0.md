## Release v2.3.0

### What's changed

Promptolution v2.3.0 removes ExperimentConfig and its string dispatch get\_\* factories and adds config-driven runs and experiment grids via Hydra.

#### Added features:

- `promptolution.experiment_grid`: config-driven single runs and whole experiment grids via Hydra
  `instantiate`: `python -m promptolution.experiment_grid`, `-m` for grids, one SLURM array job via `hydra/launcher=slurm`. Every component group is a `_target_` + its params in `conf/`.
- Restart for experiments: the experiment `name` keys the output folder; rerunning the same name
  resumes into the same folder and skips cells that already finished.
- Per-run output: `step_results.parquet`, `prompt_scores.parquet`, `runinfo.json`, and a
  `.finished` marker.
- `promptolution.utils.train_test_split` and `promptolution.utils.score_prompts`, split your data
  and score prompts on a task
- Optimizers generate `initial_prompts` from the task's `task_description` when none are given (moved here from the deleted `promptolution.helpers.run_optimization`).

#### Breaking changes:

- `promptolution.helpers` (`run_experiment`, `run_optimization`, `run_evaluation`, `get_llm`,
  `get_task`, `get_optimizer`, `get_predictor`, `get_exemplar_selector`) and `ExperimentConfig` are
  removed. Build components directly (see the README quickstart) or use `experiment_grid`.
- Every component constructor drops its `config` parameter.
- `hydra-core` is now a main dependency; the `[experiments]` extra keeps the SLURM launcher plugin
  and HuggingFace `datasets`.

**Full Changelog**: [here](https://github.com/automl/promptolution/compare/v2.2.3...v2.3.0)
